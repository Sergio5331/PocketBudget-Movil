# Colaboración

## Flujo de trabajo propuesto

1. Seleccionar una historia del backlog y definir criterios de aceptación.
2. Crear una rama corta desde `main`, por ejemplo `feature/PB01-autenticacion` o `fix/PB06-validacion`.
3. Desarrollar y verificar el cambio con commits claros.
4. Abrir un Pull Request con la historia, comportamiento resultante y evidencia de pruebas.
5. Solicitar revisión a otro integrante y resolver observaciones antes de integrar.

Cada semana los tres integrantes aportan al producto técnico mediante código, configuración, pruebas, revisión o integración verificable. Mantener credenciales y archivos de entorno locales fuera del repositorio; documentar los nombres de las variables con ejemplos sin secretos.

## Definition of Done del plan

- Funcionalidad completa conforme a la historia y sus criterios de aceptación.
- Integración con navegación, almacenamiento y módulos relacionados.
- Flujo principal sin errores críticos o bloqueantes.
- Pruebas funcionales ejecutadas y resultados registrados.
- Validaciones, permisos, errores y seguridad básica revisados cuando corresponda.
- Commits claros y Pull Request revisado cuando corresponda.
- Evidencia disponible: captura, video, prueba o versión ejecutable.
- Aprobación interna del equipo y funcionalidad lista para demostración.
